# 3-Tier Infrastructure Diagram Example

Simple example demonstrating the draw.io diagram generation feature with a classic 3-tier architecture: Load Balancer → Web Server → Database.

## Architecture

This example generates a diagram for a traditional 3-tier application infrastructure:

1. **Infrastructure Layer**: Load Balancer
2. **Application Layer**: Web Server
3. **Data Layer**: Database Server

## Usage

### 1. Install draw.io CLI

**macOS**:
```bash
brew install --cask drawio
```

**Linux (Debian/Ubuntu)**:
```bash
wget https://github.com/jgraph/drawio-desktop/releases/download/v24.7.8/drawio-amd64-24.7.8.deb
sudo dpkg -i drawio-amd64-24.7.8.deb
```

**Verify**:
```bash
drawio --version
```

### 2. Initialize Terraform

```bash
cd examples/projects/infra-3-tier-app/
tofu init
```

### 3. Generate Diagram

```bash
tofu apply
```

This will:
- Generate `docs/architecture.drawio` (draw.io XML file)
- Export `docs/architecture.drawio.png` (PNG image)

### 4. View Diagram

**Open in draw.io**:
```bash
open docs/architecture.drawio
# or on Linux:
drawio docs/architecture.drawio
```

**View PNG**:
```bash
open docs/architecture.drawio.png
```

## What Gets Generated

```
docs/
├── architecture.drawio      # Draw.io XML file
└── architecture.drawio.png  # PNG export
```

The diagram shows:
- Load Balancer (top layer)
- Web Server (middle layer)
- DB Server (bottom layer)
- Arrows indicating data flow

## Customizing the Diagram

Edit `project.tofu` and modify the `project` object in the module call:

```hcl
module "architecture_diagram" {
  source = "../../stacks/tofukit-feature-diagram-drawio"

  file_path = "docs/architecture"

  project = {
    infrastructure = [
      { name = "Load Balancer", type = "load_balancer" },
      { name = "CDN", type = "cdn" }  # Add more components
    ]

    services = [
      { name = "Web Server", type = "web_server" },
      { name = "API Server", type = "api" }  # Add more services
    ]

    databases = [
      { name = "DB Server", type = "sql" },
      { name = "Redis Cache", type = "cache" }  # Add cache layer
    ]
  }
}
```

Then run `tofu apply` to regenerate.

## Architecture Details

### Component Specifications

The `project` variable passed to the diagram module describes three components:

**Load Balancer**:
- **Name**: Load Balancer
- **Type**: load_balancer
- **Description**: Distributes traffic across web servers
- **Visual**: Rendered as trapezoid shape

**Web Server**:
- **Name**: Web Server
- **Type**: web_server
- **Description**: Handles HTTP requests and serves content
- **Visual**: Rendered as rounded rectangle

**DB Server**:
- **Name**: DB Server
- **Type**: sql
- **Description**: Primary database for application data
- **Visual**: Rendered as cylinder shape

### Data Flow

```
Client Request
      ↓
Load Balancer (distributes traffic)
      ↓
Web Server (processes request)
      ↓
DB Server (retrieves/stores data)
      ↓
Web Server (formats response)
      ↓
Load Balancer (returns to client)
      ↓
Client Response
```

## Troubleshooting

### No diagram generated

Check for errors in `tofu apply` output. Common issues:
- draw.io CLI not installed or not in PATH
- Invalid component types in project variable
- File permission issues in docs/ directory

### Diagram exists but looks wrong

The diagram is generated by Claude based on the component specifications. If the layout or appearance isn't what you expected:
1. Review the component types (must match valid types: load_balancer, web_server, sql, etc.)
2. Check Claude debug output (if `debug = true` in provider config)
3. Manually edit the `.drawio` file in draw.io desktop application

### PNG export fails

Ensure draw.io CLI supports export:
```bash
drawio -x -f png --help
```

If not supported, you can still use the `.drawio` file and export manually from draw.io desktop.
